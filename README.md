# RHO-FFT

**Hybrid-Order Federated Fine-Tuning over Decentralized Satellite Intelligence.** Research code built on
[HO-FL](https://github.com/HKU-WILL-Lab/ho-fl), a federated fine-tuning method in which every device trains the layers
above its memory cut with backpropagation (first-order) and the layers below it with forward-only gradient estimates
(zeroth-order).

The satellite scenario (`ho_fl/sat/`) runs this on a Walker constellation of 120 satellites without a ground server.
Each orbital plane has one backbone satellite that backpropagates through the whole model, four GPU satellites that
backpropagate through the top blocks only, and five inference-chip satellites that train forward-only. Zeroth-order
reports (a seed and ten scalars) are flooded and replayed on every replica; first-order updates are summed along each
plane and exchanged between the backbone satellites over a laser ring.

## Running the experiments on Colab

Open [`notebooks/RHO-FFT_colab.ipynb`](https://colab.research.google.com/github/GuangLun2000/RHO-FFT/blob/main/notebooks/RHO-FFT_colab.ipynb)
in Colab, choose a GPU runtime and run all cells. It clones this repository at the branch named by `REPO_REF` (`main`;
no token needed), builds the pinned environment and runs the experiment (`experiments/sat/e0/e0.py`) in numbered
steps, without a time limit: peak GPU memory per cut, short runs of every implemented method on EuroSAT and of
three of them on HumAID, day-long runs of every method on EuroSAT. The checks of the code (tests, regression against
upstream, correctness on the real models) are stages of the same pipeline and are not part of the notebook. It
then shows a summary and figures in the page, prints a feedback report to copy back (what the session showed and
what should change), hands over a result bundle and releases the GPU; an error in any cell leads to the same
ending. The notebook is generated by `notebooks/build_notebook.py`.

## Earlier phase (P0 to P2)

Before the satellite scenario this repository studied where each layer's update comes from in HO-FL and how one
unreliable device damages it (brief v1.1). That phase added scheduling, robust and quorum aggregation, fault
injection, probes, the dose-response experiment, supply metrics and the zeroth-order estimator check to `ho_fl/`, all
off by default. Its findings on Qwen2.5-1.5B / AG News (seed 42) shaped the satellite experiments: switching the
zeroth-order updates off changes accuracy by less than 0.2 points; averaging only first-order reports gains 1.8
points, but doubling the server step alone gains 1.7. Its deadline milestone (P3) is replaced by the satellite
scenario, and its end-to-end resilience comparison is suspended. The documents of that phase were removed from the
working tree; they are in the git history of `main` (`docs/plans/`, `docs/reports/P0.md` to `P2.md`).

# HO-FL

## Install

Python 3.11 and a CUDA GPU supporting BF16 (PyTorch 2.6.0 / CUDA 12.4):

```bash
python3 -m pip install uv
uv venv --python 3.11
uv pip install --torch-backend cu124 .
source .venv/bin/activate
```

## Train

```bash
ho-fl-train --model opt --dataset sst2 --method hofl --beta 0.75 --seed 42 --output outputs/opt-sst2
ho-fl-train --model qwen --dataset ag_news --partition dirichlet_05 --method hofl --beta 0.5 --seed 43 --output outputs/qwen-agnews
ho-fl-train --help
```

| Option | Values / Default |
| --- | --- |
| `--model` | `opt`, `qwen`, `smollm3` |
| `--dataset` | `sst2`, `boolq`, `sciq`, `ag_news`, `squad` |
| `--method` | `fedavg`, `fedprox`, `decomfl`, `hofl` |
| `--beta` | 0 to 1; default 0.75 for `hofl` |
| `--seed` | Base random seed; default 42 |
| `--partition` | `iid`; AG News also accepts `dirichlet_1`, `dirichlet_05`, `dirichlet_01` |
| `--k`, `--E`, `--q`, `--batch-size`, `--rounds` | Defaults: 6, 5, 2, 16, 160 |
| `--lr`, `--mu`, `--prox-lambda` | Defaults: 1e-5, 0.001, 0.001 |
| `--output`, `--cache-dir` | Output and download/cache directories |
| `--model-path`, `--data-path` | Optional local model and Datasets `save_to_disk` directories |
| `--manifest`, `--token-cache` | Optional local partition and tokenized-data files |
| `--device`, `--local-files-only` | Device selection and offline model loading |

Without local paths, models and datasets download automatically and client partitions are generated from `--seed`. For E=1/5/10 with equal processed-sample budgets, set `--rounds 800/160/80`, respectively.
