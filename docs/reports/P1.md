## 5 不一致之处、未解决的问题、需要决定的事项

与说明不一致之处、歧义和需要研究负责人决定的事项集中写在 `docs/plans/implementation-plan.md` 的第 4、7、8 节。与 P1 直接相关的三条：

- H1 里"范数比在 0.3 到 3 之间"这一条在 AdamW 下没有区分力；逐层余弦的随机涨落比 H1 预测的量级还大。反馈报告因此按客户端把全部零阶层合并后算余弦，并给出随机参照值 1/√d 和标准误。
- H1a 的判定在只有一个种子时标为"初步"：论文里这些运行的种子间标准差（0.4 到 0.6 个百分点）与要比较的差值同一量级。
- `ho-fl-profile` 依赖的 `ho_fl/algorithms.py` 相对上游有改动（新增一个默认关闭的关键字参数）。默认路径由冻结的上游副本逐位核对，`ho-fl-profile` 本身没有运行过。

未解决的风险：

- notebook 的环境搭建单元格从未在 Colab 上执行过。
- **G4 与固定版本的 PyTorch 不兼容。** Colab 的 G4 运行时是 Blackwell 架构的 RTX PRO 6000；按 PyTorch 论坛的说明，CUDA 12.8 构建（PyTorch 2.7.0 起）才支持这一代 GPU，上游固定的 2.6.0（CUDA 12.4）不支持。notebook 现在会先探测 GPU，固定版本用不了时自动换成 2.7.1 的 CUDA 12.8 构建并记录在结果里。这是对说明 §8 环境要求（PyTorch 2.6.0）的偏离：基线回归在同一环境里做，结论不受影响；与论文数值的对照多了一层环境差异。本机的 CPU 测试一直是在 torch 2.7.1 上通过的。在 H100 上不会触发这个回退。
- 目标 GPU 是否逐位可复现未知；多个运行共用 GPU 时是否仍逐位可复现也未知。回归检查是逐个顺序运行的，不受并行影响。
- Qwen 每次运行的耗时没有实测值，12 次运行能否放进一次会话要等预检计时。放不进的会被跳过并列在报告里。

| H1a（稀释） | 无法判断：偏向采样没有收益（G_β = −0.01）；且第二个条件不成立 | G_C = +1.78，G_lr = +2.59（A×3），A×2 为 +1.72 |

**计划外的发现。**

- 第 160 轮时所有臂的准确率仍在上升，最终准确率主要反映学习速度。只放大服务器步长（A×3）超过了 FedAvg。
- 关掉零阶后偏向采样的曲线与不关时重合，前期同样比均匀采样快，所以这个加速不来自零阶方差的下降。
- DeComFL 的 55.70 与第 0 轮的准确率相同：纯零阶在这个预算下没有学到东西。
- 关掉零阶省 38% 的前向当量（56 对 90），实测每轮 1.6 秒对 3.0 秒。

**实测耗时（单独占用 GPU）。** HO-FL 每轮 3.0 秒，关掉零阶 1.6 秒，FedAvg 2.0 秒，DeComFL 4.2 秒；每次评估约 11.8 秒；显存峰值 4.4 到 14.5 GiB。两个运行共用 GPU 时 HO-FL 每轮 5.2 秒，并行带来的吞吐提升很小。
