# Satellite scenario experiments

One directory per experiment of the brief (`docs/RHO-FFT-agent-brief-v2.md`, section 10): its configuration files and
the pipeline script that runs it. Results go to `outputs/sat/` (or the `--root` given), traces and partitions to
`cache/sat/`; neither is tracked.

| Directory | Experiment | State |
| --- | --- | --- |
| `e0/` | Gate G0: correctness, memory, cost, first learning signals, alignment with HO-FL | ready to run on Colab |
| `e1/` ... `e4/` | Main comparison, contributions, faults, topology | follow after gate G0 |

## How a Colab session works

The experiments run on Colab, one session at a time, and each session feeds the next:

1. A session is run for a short list of questions. Every run answers one of them and names the decision that
   depends on the answer; a run nobody would act on is not scheduled. A stage does not start when a stage it builds
   on did not pass. Checks of the code are not scheduled on Colab (decision of the research lead, 2026-11-25): the
   CPU tests a change touches run locally before it is pushed, and the checks stay callable as stages of the pipeline.
2. The pipeline ends with a feedback report (`e0/digest.py` is the pattern): the state of the gate, the answers, the
   findings with the file to change or the decision to take, the measured cost of what comes next, and what to run
   in the following session.
3. The research lead copies the report back. Code and notebook are adjusted from it and pushed, then the next session
   runs.
4. The notebook (`notebooks/RHO-FFT_colab.ipynb`, generated by `notebooks/build_notebook.py`) prints the report
   between two marker lines, downloads the result bundle and releases the GPU, at the end and after any error.
